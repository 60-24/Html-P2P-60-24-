⚙️ AAOS v1.0

AI Agent Operating System

P2P 60-24 OneClick Evo

Misja: Stworzyć środowisko współpracy wielu agentów AI, w którym każdy agent wykonuje wyspecjalizowane zadania, zachowując pełną zgodność z konstytucją techniczną projektu.
Zasada główna: Agent nie tworzy własnej wizji systemu. Agent realizuje uzgodnioną wiedzę systemową.

⚡ Fundamentalne Zasady Działania

🎯 Czysty Przepływ Wiedzy

Wiedza → Architektura → Specyfikacja → Kod → Test → Ewolucja

Nigdy: Kod → przypadkowa architektura → chaos

✅ Agent musi

• Analizować kontekst przed działaniem
• Wykrywać sprzeczności
• Dokumentować decyzje
• Tworzyć rozwiązania modularne
• Respektować istniejące interfejsy

❌ Agent nie może

• Zmieniać fundamentów bez zatwierdzenia
• Usuwać funkcji bez analizy
• Tworzyć duplikatów
• Ignorować dokumentacji
• Pracować w próżni bez kontekstu

📦 Zasada Minimalnej Zmiany

• Najmniejsza liczba zmian
• Największa kompatybilność
• Możliwość cofnięcia
• Pełna dokumentacja
• Zero zaskoczenia systemowe

🧠 Pamięć Systemu — 3 Poziomy

📜 LEVEL 1
Konstytucja Projektu
(niezmienna, święta)
🏗️ LEVEL 2
Architektura & ADR
(zmieniana kontrolowanie)
💾 LEVEL 3
Kod Źródłowy
(najbardziej zmienny, ale zawsze zgodny)

Każdy agent musi znać pełną hierarchię. Kod bez Architektury = chaos. Architektura bez Konstytucji = błędy fundamentalne.

🔄 Kontrola Zmian — Change Request Protocol

Jeżeli agent odkryje problem lub potrzebuje zmian, nie zmienia sam. Tworzy Change Request.

1
Agent odkrywa problem
Coś nie zgadza się z architekturą lub konstytucją
2
Tworzy CHANGE REQUEST
Problem, Propozycja, Wpływ, Priorytет
3
Governor (A0) analizuje
Czy to warte dyskusji? Czy może czekać?
4
Odpowiedni Architekci (A1, A2) oceniają
Konflikt? Implikacje? Alternatywy?
5
HUMAN OWNER decyduje
APPROVE / REJECT z uzasadnieniem
6
Dokumentacja i wdrożenie
Zmiana idzie do LEVEL 1/2 + powiadamiamy wszystkich agentów
